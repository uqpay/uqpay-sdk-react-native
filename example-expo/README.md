# UQPAY React Native — sample app (Expo variant)

> ## Expo Go is not supported
>
> `@uqpay/react-native` wraps the native iOS and Android UQPAY SDKs, so it
> cannot run inside Expo Go — Expo Go ships a fixed set of native modules and
> yours is not one of them. `init()` throws a clear error naming Expo Go if you
> try (AC RN-INT9).
>
> Use a **development build**: `npx expo prebuild` + `npx expo run:ios` /
> `run:android` locally, or `eas build --profile development`. Everything below
> assumes that.

This is the **same app** as the bare React Native sample in [`../example`](../example) —
the screens in `src/` are a copy, line for line. That is the point: nothing
about the integration changes under Expo. The differences are exactly two:

| | Bare RN (`example/`) | Expo (`example-expo/`) |
|---|---|---|
| Native projects | checked in (`ios/`, `android/`) | generated by `npx expo prebuild`, gitignored |
| iOS 3DS return URL scheme | hand-written `CFBundleURLTypes` in `Info.plist` | `app.json` — `scheme` + the UQPAY config plugin |

Android needs no configuration in either app: the native SDK handles the bank
return inside its own Activity.

The reference merchant backend is **shared** with the bare sample and is not
duplicated here — it lives in [`../example/backend`](../example/backend) and
reads its own `../example/.env`.

## 1. Configure

```bash
cp example-expo/.env.template example-expo/.env
$EDITOR example-expo/.env          # fill UQPAY_CLIENT_ID
node example-expo/scripts/gen-env.mjs
```

`gen-env.mjs` writes `example-expo/src/env.generated.ts` with **exactly three**
values. It is gitignored, and the `start` / `ios` / `android` / `prebuild`
scripts regenerate it for you.

| Variable | Read by | Meaning |
|---|---|---|
| `UQPAY_ENVIRONMENT` | **app** | `sandbox` (default) or `production` |
| `UQPAY_CLIENT_ID` | **app** | your merchant client id |
| `UQPAY_MERCHANT_BACKEND_URL` | **app** | where the app finds the backend (default `http://localhost:8787`) |
| `UQPAY_API_KEY` | backend only | ⚠️ the merchant API key. The app must **never** read it |
| `UQPAY_WEBHOOK_URL` | backend only | the public URL you registered for webhooks |
| `UQPAY_ON_BEHALF_OF` | backend only | optional UQPAY Connect sub-account |

The app reads three of those and never names the API key — a Jest tripwire
(`src/__tests__/secrets.test.ts`) fails the build if any file under
`example-expo/src` or `example-expo/scripts` so much as mentions it, or names
the UQPAY API host (AC RN-SEC3, RN-FLOW4).

The backend reads its **own** copy in `../example/.env`; fill that one in too,
with the same client id and the API key.

## 2. Run the backend

```bash
node example/backend/server.mjs
```

It starts even with an empty `.env` and tells you what is missing. Leave it in
its own terminal. Details: [`../example/backend/README.md`](../example/backend/README.md).

## 3. Generate the native projects and run

```bash
# from the repo root, once
yarn

cd example-expo
npx expo prebuild            # writes ios/ and android/ — both gitignored
npx expo run:ios             # or: npx expo run:android
```

`prebuild` is safe to re-run: it regenerates `ios/` and `android/` from
`app.json`, and the UQPAY plugin never duplicates what it added last time. Both
directories are build output — never commit them, never hand-edit them.

### EAS Build

```bash
npx eas-cli build --profile development --platform ios
```

EAS runs the same `prebuild` in the cloud, so the config plugin applies there
identically. Use a **development** (dev-client) profile while you are iterating,
then `preview` / `production` for a shareable build. You do not need `ios/` or
`android/` in git for EAS.

| | Backend URL used | Notes |
|---|---|---|
| iOS simulator | `http://localhost:8787` | works as configured; `NSAllowsLocalNetworking` is set in `app.json` for the cleartext dev backend |
| Android emulator | `http://10.0.2.2:8787` | rewritten automatically; the Home screen says so |
| Physical device | your LAN IP | set `UQPAY_MERCHANT_BACKEND_URL` and re-run `gen-env.mjs` |

### The config plugin (3DS / wallet return)

`app.json` carries:

```json
{
  "expo": {
    "scheme": "uqpayexpoexample",
    "plugins": [["@uqpay/react-native", { "iosUrlScheme": "uqpayexpoexample" }]]
  }
}
```

The app returns from the bank through `uqpayexpoexample://return`
(`src/config.ts`). On **iOS** the scheme must appear in `CFBundleURLTypes` or
3DS opens and never comes back; on **Android** nothing is required.

Two things register that scheme, and they cooperate:

- **Expo itself** turns `expo.scheme` into a `CFBundleURLTypes` entry (and an
  Android `VIEW` intent filter).
- **The UQPAY plugin** adds its own entry, named `com.uqpay.return` — *unless*
  the scheme is already registered, which is the case here. So in this app the
  plugin is deliberately a no-op on iOS and does nothing at all on Android.

Drop `expo.scheme`, or point `iosUrlScheme` at a different scheme, and the
plugin writes the `com.uqpay.return` entry itself. Either way you end up with
the scheme registered exactly once. `iosUrlScheme` is optional: without it the
plugin falls back to `expo.scheme`, then to `ios.bundleIdentifier`.

## 4. Sandbox notes — read before testing

| | |
|---|---|
| **Cards** | Use the sandbox test cards with **exactly** this expiry/CVC (the ACS rejects anything else with `3ds_failed`): **Mastercard 3DS** `5521 9700 7999 8012`, **10/28**, CVC **001** → `SUCCEEDED` (the only 3DS-enrolled card, frictionless). **UnionPay** `6250 9470 0000 0014`, 12/33, 123 → `SUCCEEDED` without 3DS. The quickstart Mastercards `5346 …8117` / `5413 …4047` are not 3DS-enrolled and always fail through the sheet. A **Visa** 3DS card returns `system_error` — sandbox limitations, not SDK bugs. |
| **Wallets** | `paynow`, `tosspay` and `naverpay` return `system_error` server-side. |
| **QR wallets** | ⚠️ **Sandbox QR wallets settle on REAL rails.** Scanning a sandbox QR with a real wallet app moves real money. Get budget/approval first; do not scan casually. |
| **Tokens** | One active token per merchant. Minting from a second machine invalidates the first tester's session — coordinate before running two backends. |
| **Intents** | Expire 30 minutes after creation. |
